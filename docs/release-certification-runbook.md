# Release Certification Runbook (Sprint 3)

This is the operator runbook for taking codex-swift from "all P0–P5 green +
P6/P7/P8 partial" to **production release** by executing the P6/P8/P9 gates
that require credentials and physical hardware Claude cannot access from a
dev session.

All scripts referenced below already exist under `tools/e2e/`. The verifier
contract is already wired (`verify_release_evidence.py` + strict mode). What
remains is **execution**.

## Required inputs (gate them at the door)

Before booking a release window, the operator must hold all of the following.
Missing any one of them blocks `g9_final_rehearsal.sh --strict`.

| Input | How to obtain | Verifier env var |
|---|---|---|
| OpenAI API key with live access | OpenAI dashboard | `OPENAI_API_KEY` |
| Apple Developer ID Application certificate | Apple Developer portal → "Developer ID Application", install on the release Mac keychain | (used implicitly by `codesign`) |
| Apple notarization profile saved in keychain | `xcrun notarytool store-credentials <profile-name>` with App Store Connect API key | `CODEXKIT_NOTARY_PROFILE=<profile-name>` |
| Physical-footprint entitlement signing identity | Hardened-runtime entitled cert (the same Developer ID Application identity above, with the entitlement plist permitting `task_set_phys_footprint_limit`) | (used implicitly by `g6_physical_footprint.sh`) |
| A clean macOS 26 box (fresh OS install or wiped VM) | Reserve a dedicated machine | `CODEXKIT_TRUE_CLEAN_MACHINE=1` + attestation JSON |
| Operator-signed clean-machine attestation JSON | Generated by `tools/e2e/clean_machine_attestation.py` | `CODEXKIT_CLEAN_MACHINE_ATTESTATION=<path>` |
| 24+ hour wall-clock window | Calendar block | `CODEXKIT_SOAK_SECONDS=86400` |
| Network egress: OpenAI + Apple notary + ChatGPT issuer | Standard internet | n/a |

## Phase 0 — Preflight (cheap, do these first)

These are non-mutating. Run them from any Mac with a release build.

```bash
# 1. The audit-only readiness check. Reports what's missing, no execution.
tools/e2e/strict_release_readiness.py

# 2. With saved notary profile, prove notarytool can authenticate.
CODEXKIT_NOTARY_PROFILE_LIVE_CHECK=1 \
CODEXKIT_NOTARY_PROFILE=<profile-name> \
  tools/e2e/notary_profile_readiness.py

# 3. Confirm the entitled binary can install a physical-footprint cap.
CODEXKIT_FOOTPRINT_LIVE_CHECK=1 \
  tools/e2e/physical_footprint_readiness.py
```

If any of these fail, **stop** and fix before the release Mac is booked.

## Phase 1 — Code & test gate (no special hardware)

On the release Mac (or any Mac with the build env), confirm the baseline:

```bash
export OPENAI_API_KEY=<key>
swift build -c release
swift test                          # 491 tests expected, live included
tools/e2e/g0_baseline.sh
tools/e2e/g5_full_corpus.sh         # 283 deterministic + 28 live
```

If `g5` fails, the release is not viable — fix and rerun before continuing.

## Phase 2 — Lifecycle: signing + notarization (P6)

```bash
# Build, sign, notarize, staple, and verify Gatekeeper acceptance.
export CODEXKIT_NOTARY_PROFILE=<profile-name>
export CODEXKIT_EVIDENCE_DIR=$HOME/codexkit-release-evidence/$(date -u +%Y%m%dT%H%M%SZ)
mkdir -p "$CODEXKIT_EVIDENCE_DIR"

tools/e2e/g6_lifecycle.sh           # writes lifecycle JSON under $CODEXKIT_EVIDENCE_DIR
```

Expected evidence: `$CODEXKIT_EVIDENCE_DIR/g6_lifecycle.json` with
`notarytoolStatus: "Accepted"`, `stapleStatus: "success"`, and Gatekeeper
`source=Notarized Developer ID`.

If notarization fails: capture the `notarytool log` and look at the rejection
reason. Common failures are missing hardened-runtime, missing entitlements,
or unsigned framework dylibs. Fix at the signing step, do **not** ship a
workaround.

## Phase 3 — Clean machine + true reboot (P6)

On the **certified clean macOS 26 box**:

```bash
# Generate the attestation JSON. This must be filled in by the operator,
# not auto-filled.
tools/e2e/clean_machine_attestation.py \
  --operator "<your name>" \
  --machine-purpose "codex-swift release certification 2026-Q2" \
  > /tmp/clean-machine-attestation.json

# Inspect the JSON, confirm all assertions are true, and bind it to this host.
tools/e2e/clean_machine_attestation.py --rebind /tmp/clean-machine-attestation.json

export CODEXKIT_CLEAN_MACHINE_ATTESTATION=/tmp/clean-machine-attestation.json
export CODEXKIT_TRUE_CLEAN_MACHINE=1
export CODEXKIT_EVIDENCE_DIR=$HOME/codexkit-release-evidence/$(date -u +%Y%m%dT%H%M%SZ)
mkdir -p "$CODEXKIT_EVIDENCE_DIR"

tools/e2e/g6_clean_machine.sh       # install on empty $CODEX_HOME

# Two-phase reboot proof.
tools/e2e/g6_true_reboot_resume.sh prepare > /tmp/reboot-prepare.json
sudo shutdown -r now
# … wait for the box to come back …
tools/e2e/g6_true_reboot_resume.sh verify /tmp/reboot-prepare.json
export CODEXKIT_TRUE_REBOOT_EVIDENCE=$CODEXKIT_EVIDENCE_DIR/g6_true_reboot_resume.json
```

Expected: `$CODEXKIT_EVIDENCE_DIR/g6_clean_machine.json` and
`$CODEXKIT_EVIDENCE_DIR/g6_true_reboot_resume.json` both present, with
`assertions.*` keys all `true`, and the true-reboot proof carrying a `verifiedAt`
strictly after `preparedAt` and a kernel boot time strictly after both.

## Phase 4 — Hardening + 24 h soak (P8)

Schedule on the certified machine; the operator should **not** use this Mac
for anything else during the soak window.

```bash
# Physical-footprint kernel enforcement — needs entitled binary.
CODEXKIT_FOOTPRINT_EXPECT_ENFORCED=1 \
  tools/e2e/g6_physical_footprint.sh

# Fault containment matrix.
tools/e2e/g6_fault.sh

# The 24 h soak. This is the wall-clock blocker. Live = on.
export CODEXKIT_SOAK_SECONDS=86400        # 24h
export CODEXKIT_SOAK_SESSIONS=50
export CODEXKIT_SOAK_TURNS=12
export CODEXKIT_SOAK_LIVE=1
export CODEXKIT_SOAK_LIVE_SECONDS=3600    # at least 1 h live OpenAI
export CODEXKIT_SOAK_LIVE_SESSIONS=4
export CODEXKIT_SOAK_LIVE_TURNS=3
export CODEXKIT_SOAK_LIVE_CODING=1
export CODEXKIT_LIVE_CODING_SESSIONS=2
export CODEXKIT_LIVE_CODING_TURNS=3

tools/e2e/g6_soak.sh
```

Expected: `g6_soak.json` with mock + live + live-coding manifests all matching
configured sizes, flat fd/RSS trend samples, and broker refresh-storm proof
showing exactly one upstream refresh with 199+ coalesced callers.

If the soak fails partway through, **do not retry over the partial evidence
directory** — the strict verifier indexes hashes and would catch the stale
artifacts. Start a fresh `CODEXKIT_EVIDENCE_DIR` and re-run from this phase.

A pass writes a final manifest under `$CODEXKIT_EVIDENCE_DIR` with the
`g9_final_rehearsal` gate marker, UTC `createdAt`, host hardware UUID, and
hashed references to every child evidence JSON produced in phases 2–5.

## What to do if a gate fails

The strict verifier is intentionally unforgiving: it will reject a release
bundle for missing hashes, mismatched basenames, unexpected secrets in
evidence files, late-by-a-minute true-reboot timestamps, etc. When it fails:

1. Read the verifier output carefully — it names the exact assertion key.
2. Look at the relevant child evidence JSON in `$CODEXKIT_EVIDENCE_DIR`.
3. Cross-check the producing script in `tools/e2e/` to understand what
   contract was violated.
4. If the contract is wrong (e.g. an assertion key changed without
   verifier update), file an issue and fix in code, **not** by tweaking the
   JSON by hand.

## Common operator pitfalls

- **Editing evidence JSON manually.** Strict verifier hashes every indexed
  file; any edit changes the hash and breaks the manifest. Always regenerate.
- **Sharing a clean machine between release attempts.** The "clean machine"
  contract requires `$CODEX_HOME` empty at the start. If you want to retry on
  the same box, use `tools/e2e/g6_clean_machine.sh --purge-codex-home` first.
- **Not setting `CODEXKIT_NOTARY_PROFILE` for `notarytool`.** Without it, the
  signing path falls through to ad-hoc signing and Gatekeeper rejects.
- **Reusing the soak evidence dir.** The 24 h soak collects timestamped
  trend samples; mixing with earlier data poisons the analysis.
- **Hitting Ctrl-C on g6_soak.** Soaks must run to completion under their
  own deadline; partial runs are intentionally rejected by strict mode.
- **Storing API keys in the evidence dir.** The verifier scans every indexed
  file for the configured OpenAI key and rejects the bundle if found.
