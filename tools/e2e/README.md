# macOS Completion E2E Gates

These scripts are thin wrappers around the existing Swift tests and daemon
smokes. They intentionally fail fast and do not maintain a separate expected
failure list.

| Gate | Purpose |
|---|---|
| `g0_baseline.sh` | Release build, full non-live suite, stdio/WS/UDS daemon smokes, live suite when `OPENAI_API_KEY` is set. |
| `g1_transport.sh` | Wire/protocol and local transport contracts plus app-server method coverage, including config write/readback and external-agent CONFIG/MCP_SERVER_CONFIG/HOOKS/SKILLS/COMMANDS/SUBAGENTS/AGENTS_MD/PLUGINS/SESSIONS detect/import/idempotency, stdio/WS/UDS smokes, a real UDS JSONL full turn through spawned workers, and a stdio-to-UDS compatibility bridge. |
| `g2_model_persistence.sh` | Model request shaping/failure behavior, persistence, Rust-shaped rollout read/write compatibility for core records, resume, byte-faithful prompt continuity, live model suite when available. |
| `g3_tools_sandbox.sh` | Tools, sandbox policy/profile generation, kernel denial coverage, symlink containment, and adversarial tool tests. |
| `g4_auth_broker_memories.sh` | Auth, broker, MCP, hooks, memory flows, and live memory/MCP checks when available. |
| `g5_full_corpus.sh` | Pinned Codex schema-oracle bootstrap/diff, generated TypeScript manifest parity, typed request-field parity, concrete typed response schema parity, explicit generic response-policy coverage, generic response schema parity for generated and source-derived response schemas, deterministic app-server transcript replay including durable thread-state and metadata oracle parity, real `command/exec`, `fs/*`, direct `fuzzyFileSearch`, and `config/value/write`/`config/batchWrite` behavior oracle parity, Swift goal/memory/archive/external-agent state coverage, Swift release-binary mocked-turn event-stream/durable-readback replay, release-evidence verifier/readiness/preflight/attestation/notary-profile/physical-footprint selftests, model-backed prompt/tool/compaction/memory/persistence replay, deterministic protocol, prompt, persistence, tools, MCP, failure-mode corpus, and live OpenAI suite when available. |
| `g6_hardening_smoke.sh` | Adversarial/failure campaign, including persistence fsync `EINTR` retry and synthetic fsync-stall durability coverage, macOS tool fork-bomb process-group containment, worker isolation, resource primitives, model-transport fault campaign (`ModelClientTests` + `OpenAIClientFailureTests`), and release build. |
| `g6_lifecycle.sh` | Render/stage launchd plists, broker resident Unix-listener shape, lifecycle install/status/uninstall verbs, ad-hoc and Developer ID hardened-runtime signing verification, user launchd bootstrap/KeepAlive restart smoke, hardened-runtime entitlements, signing/notarization runbook, generated operations runbook with concrete status/log/socket/restart/quarantine/update/rollback/evidence/uninstall commands, and release lifecycle artifacts. |
| `g6_codesign_smoke.sh` | Stage release binaries, ad-hoc sign with generated entitlements and hardened runtime, verify strict signatures, and inspect runtime/entitlement metadata. |
| `g6_developer_id_sign_smoke.sh` | Stage release binaries, sign with the first available Developer ID Application identity, verify Team ID/runtime/entitlements, prove signed-only artifacts are rejected as unnotarized when no notary profile is configured, and optionally notarize/staple/assess a signed DMG when `CODEXKIT_NOTARY_PROFILE` is set. Set `CODEXKIT_EVIDENCE_DIR` to persist JSON evidence with identity, Team ID/runtime/entitlement checks, signed-only Gatekeeper rejection, DMG hash/signature, notary acceptance output, stapler staple/validate output, and Gatekeeper assessment output requiring exact `status: Accepted`, exact stapler success lines, exact `: accepted`, and exact `source=Notarized Developer ID` lines when run with a notary profile. |
| `notary_profile_readiness.py` | Optional strict-release preflight for saved notary credentials. Run with `--profile <CODEXKIT_NOTARY_PROFILE>` or set `CODEXKIT_NOTARY_PROFILE_LIVE_CHECK=1` for `strict_release_readiness.py`; it uses `xcrun notarytool history --keychain-profile ... --output-format json` to validate the keychain profile without submitting an artifact. |
| `notary_profile_readiness_selftest.py` | Mocked selftest for the notary readiness helper. It proves valid JSON history passes, failed `notarytool` exits are rejected, and non-JSON output is rejected. |
| `g6_clean_machine.sh` | Empty temp install/LaunchAgents/CODEX_HOME roots, first initialize/turn, state creation, explicit purge uninstall, and post-uninstall launchd/file cleanup assertions. Set `CODEXKIT_EVIDENCE_DIR` to persist JSON evidence with host/version, labels, thread id, loaded/uninstalled status snapshots, and assertion booleans for first-thread creation, spawned-worker log evidence, worker-ready log evidence, install-root removal, LaunchAgent plist removal, and CODEX_HOME purge. Set `CODEXKIT_TRUE_CLEAN_MACHINE=1` only when this is being run on the clean hardware/VM release target; strict final rehearsal also requires `CODEXKIT_CLEAN_MACHINE_ATTESTATION=<json>` with `trueCleanMachine: true`, `operator`, a timezone-aware ISO-8601 UTC timestamp, all-true assertion booleans whose keys exactly match the required clean-machine cleanup assertion set, loaded/uninstalled status transcripts proving both launchd labels transitioned loaded -> not-loaded, and `host.hardwareUUID` matching the current machine. The gate preflights this attestation before install work begins. |
| `clean_machine_attestation.py` | Generate strict clean-machine attestation JSON for a release target. It requires an operator and every clean-machine assertion flag explicitly, binds the attestation to the current host hardware UUID, and writes JSON suitable for `CODEXKIT_CLEAN_MACHINE_ATTESTATION`; it does not infer cleanliness automatically. |
| `clean_machine_attestation_selftest.py` | Fast selftest for attestation generation. It proves a complete synthetic assertion set produces the expected JSON shape and that missing assertion flags or a blank operator are rejected. |
| `g6_blue_green.sh` | Prove versioned lifecycle release staging plus `promote-worker` swap/rollback: a quiet spawned `codex-session` worker survives, newly spawned sessions use green, then rollback sends new sessions back to blue. Set `CODEXKIT_EVIDENCE_DIR` to persist JSON evidence with the `g6_blue_green` gate marker, timezone-aware UTC `createdAt`, host/version/hardware UUID, distinct blue/green/rollback thread IDs, per-thread completion counts, blue/green worker launch counts, daemon survival proof, install-root path, and exact promotion/rollback assertion keys. |
| `g6_reboot_resume.sh` | Temp launchd install, durable thread creation, SIGKILL daemon restart, fresh-client `thread/resume`, continued turn persistence, and uninstall cleanup. Set `CODEXKIT_EVIDENCE_DIR` to persist JSON evidence with the `g6_reboot_resume` gate marker, timezone-aware UTC `createdAt`, host/version/hardware UUID, labels, old/new daemon PIDs, thread id, resumed turn count, loaded/uninstalled status snapshots, and assertion booleans for same-thread resume, resumed turn count, spawned-worker log evidence, and worker-ready log evidence. |
| `g6_true_reboot_resume.sh` | Two-phase real reboot gate. Run `CODEXKIT_REBOOT_PHASE=prepare`, reboot the Mac, then run `CODEXKIT_REBOOT_PHASE=verify`; prepare records kernel boot time, hardware UUID, same-thread id, and a timezone-aware UTC `preparedAt`, verify requires the kernel boot time to change and be later than prepare, requires the hardware UUID to match, resumes the same thread, records a timezone-aware UTC `verifiedAt` after the verify boot, writes verified `trueOSReboot` evidence, and uninstalls. Use `CODEXKIT_REBOOT_PHASE=cleanup` to remove prepared state. |
| `g6_active_turn_crash.sh` | Temp launchd install with slow mock model, kill `codexd` during an active turn, restart, fresh-client resume, verify the interrupted turn remains visible and a later turn completes. Set `CODEXKIT_EVIDENCE_DIR` to persist JSON evidence with the `g6_active_turn_crash` gate marker, timezone-aware UTC `createdAt`, host/version/hardware UUID, labels, old/new daemon PIDs, thread id, pre/post recovery turn status snapshots, loaded/uninstalled status transcripts, and assertion booleans for same-thread resume, interrupted-or-in-progress active turn preservation, later completed turn, recovered turn count, daemon PID change, spawned-worker log evidence, and worker-ready log evidence. |
| `g6_poison_worker.sh` | Production spawned-worker containment: swap `CODEXKIT_SESSION_BIN` to a worker that exits immediately, prove codexd and a quiet loaded session survive, then restore the real worker and prove new sessions recover. Set `CODEXKIT_EVIDENCE_DIR` to persist JSON evidence with the `g6_poison_worker` gate marker, timezone-aware UTC `createdAt`, host/version/hardware UUID, distinct quiet/poisoned/recovered thread IDs, per-thread completion counts, healthy/poison worker launch counts, daemon PID/survival proof, poisoned-turn outcome, and exact containment assertion keys. |
| `g6_physical_footprint.sh` | Build/sign a small macOS probe that calls `task_set_phys_footprint_limit`, exceeds the cap, and records whether the kernel terminates it. Local mode records explicit degradation when the cap is rejected or ineffective; strict final rehearsal sets `CODEXKIT_FOOTPRINT_EXPECT_ENFORCED=1` and requires the physical-footprint gate marker, host hardware UUID, timezone-aware UTC probe start/finish timestamps in monotonic order, set success, no contradictory set failure, allocation beyond the cap in the captured output, SIGKILL termination after the cap was set, no survived-allocation path, no malloc/allocation-failure path, and reported max allocation matching the raw `ALLOCATED` samples. |
| `physical_footprint_readiness.py` | Optional strict-release preflight for physical-footprint enforcement. It runs `g6_physical_footprint.sh` with `CODEXKIT_FOOTPRINT_EXPECT_ENFORCED=1` in a temporary evidence directory and validates the result with the strict physical-footprint verifier, so unsupported local hosts fail before a full release rehearsal. Set `CODEXKIT_FOOTPRINT_LIVE_CHECK=1` for `strict_release_readiness.py` to run it. |
| `physical_footprint_readiness_selftest.py` | Mocked selftest for the physical-footprint readiness helper. It proves enforced evidence passes, degraded evidence is rejected by the strict verifier, and failing probe scripts are rejected. |
| `bounded_primitives_probe.py` | Evidence-producing queue/ring saturation probe. It runs the Swift adversarial tests for blocking bounded channels, reject-newest overload accounting, coalescing-ring floods, concurrent overwrite-ring pushes, and head/tail-buffer adversarial truncation, then emits JSON consumed by `g6_soak.sh` and the strict release verifier. |
| `g6_soak.sh` | Configurable soak gate over the release `codexd` binary: Swift bounded queue/ring saturation probe, spawned multi-session turns, quiet-vs-noisy TTFT/output-rate SLO assertions in the deterministic tier, noisy payloads, deterministic tool-loop auto-compaction pressure, MCP stdio fixture churn/status probes, slow-client listener isolation probe, launchd-shaped `codex-broker --listen unix://` refresh-storm stats probe, post-completion rollout/SQLite durability probes with p99 assertion, list/read/resume probes, fd/RSS/worker-count trend metrics, optional live OpenAI multi-session turns, and optional release-binary live multi-session coding verification through spawned workers. The live-coding tier defaults to two sessions x three turns, retries with corrective live turns when the model misses the required JavaScriptCore code-mode path, includes an iterative debug/fix turn with JSON evidence that the regression failed before repair and passed after repair, then restarts `codexd` and verifies `thread/resume` plus per-workspace tests. Set `CODEXKIT_EVIDENCE_DIR` to persist per-phase JSON plus a manifest covering bounded-primitives, mock, live, and live-coding metrics; the manifest carries the `g6_soak` gate marker, timezone-aware UTC `createdAt`, and host hardware UUID when available; mock and live soak evidence include measured start/end/elapsed wall-clock fields plus per-session thread/workspace/turn details; manifest assertions require completed turns to meet `sessions * turns` both in aggregate and for each distinct session, repeated resource-trend samples with flat fd/RSS growth and bounded worker count, bounded-channel blocking/reject-newest, coalescing-ring, overwrite-ring, and head/tail-buffer adversarial tests to pass, require the broker stats probe to show one upstream auth refresh, 199+ coalesced callers, owner-only durable auth-store permissions, and resident service behavior after client EOF, require live-coding sessions to have unique thread IDs, workspaces, tags, durable completed-turn counts, per-session tool-completion counts, per-session `code` tool-completion counts for code-mode source that calls `shell` through `callTool`, and debug/fix trace markers matching the session tag, and strict verification requires both mock and live measured elapsed seconds to meet their requested durations. The strict final manifest must index and hash the bounded-primitives/mock/live/live-coding phase files named by the soak manifest, and those files must match the embedded phase payloads. Use `CODEXKIT_SOAK_SECONDS=86400 CODEXKIT_SOAK_SESSIONS=50` for the 24-hour release tier. |
| `g6_noisy.sh` | Heavier noisy-neighbor preset over `g6_soak.sh`, including deterministic quiet-session degradation assertions, tool-loop compaction pressure, MCP churn, slow-client isolation, rollout/SQLite durability p99 checks, `CODEXKIT_EVIDENCE_DIR` JSON evidence passthrough, and configurable `CODEXKIT_NOISY_*` environment variables. |
| `g6_fault.sh` | Fault-containment gate combining adversarial/resource tests, production spawned-worker poison containment, and the real launchd SIGKILL restart/uninstall smoke. Set `CODEXKIT_EVIDENCE_DIR` to persist JSON evidence with the `g6_fault` gate marker, timezone-aware UTC `createdAt`, host/version/hardware UUID, child evidence references for `g6_hardening_smoke`, `g6_poison_worker`, and `g6_launchd_smoke`, and exact aggregate assertion keys. `g6_hardening_smoke` also emits its own evidence artifact proving the adversarial/failure-mode campaign, macOS tool fork-bomb process-group containment, worker-isolation/infrastructure primitive suite, model-transport fault campaign, and release build each passed; strict fault verification rejects aggregate-only hardening claims without that child artifact. |
| `g6_launchd_smoke.sh` | Direct user-domain launchd smoke through temp install/status/uninstall: bootstrap, probe broker/codexd sockets, SIGKILL, verify restart, bootout. Set `CODEXKIT_EVIDENCE_DIR` to persist JSON evidence with the `g6_launchd_smoke` gate marker, timezone-aware UTC `createdAt`, host/version/hardware UUID, labels, loaded/uninstalled launchd status transcripts, old/new broker and codexd PIDs, pre/post restart turn count, and exact restart assertion keys. |
| `g9_final_rehearsal.sh` | Composes the release rehearsal path: release build, Developer ID/notary evidence, Keychain storage, clean install/first turn/purge uninstall, durable resume after service restart, blue/green worker promotion/rollback, stdio/UDS/TCP transport smokes, live stdio smoke when available, worker fault containment, active-turn crash recovery, physical-footprint evidence, soak/noisy-neighbor/live-coding evidence, evidence secret scan, and final manifest. In strict mode it preserves the clean-machine attestation JSON as a hashed evidence artifact and copies true-reboot evidence into the bundle when needed. The final manifest carries the `g9_final_rehearsal` gate marker, timezone-aware UTC `createdAt`, host hardware UUID when available, the exact current-run evidence files it summarizes, excludes stale pre-existing JSON from a reused `CODEXKIT_EVIDENCE_DIR`, and records SHA-256 hashes for each indexed artifact. | `strict_release_readiness.py` | Fast strict-release readiness auditor. | `strict_release_readiness_selftest.py` | Negative selftest for the readiness auditor.
